# SOIT v1.2.0 Gateway Release Notes

Status: release candidate notes. Publish only after the release commit is
tagged as `v1.2.0` and `quality.yml` and `security.yml` pass on that commit.

## Highlights

- OpenAI-compatible gateway: `/v1/chat/completions` (whole or streamed, with
  tools, images and structured output), `/v1/models`, `/v1/embeddings`,
  `/v1/images/generations` and `/v1/images/edits`. An OpenAI SDK, LangChain
  or the OpenAI Agents SDK pointed at SOIT with a SOIT API key works
  unchanged, and every call is a governed run with its id in the
  `x-soit-run-id` header. See [docs/gateway.md](../gateway.md).
- Keys with their own limits: calls per minute and per 24 hours, tokens per
  UTC day, allowed addresses (behind proxies named in `TRUSTED_PROXIES`) and
  allowed models, applied on top of the owner's limits.
- Service principals: non-human callers with a human owner and a workspace
  role, which keys can be issued to, so runs, costs and audit name the
  pipeline rather than the person who set it up.
- Budgets: per workspace, key, member or principal, or agent, per UTC day or
  month. A hard stop refuses model and tool calls once spent with `402
  budget_exhausted`; thresholds notify owners, admins and team channels once
  per period.
- Virtual models: `vmodel:{slug}` names an ordered list of up to eight
  models, tried in turn when a target is unavailable or fails in a way
  another provider might not.
- Content-free runs: a workspace or a key can store prompts, outputs and
  error text as a length and a hash while statuses, tokens, costs and timings
  are recorded as before.
- Usage you can read by entry and key: runs record their `source` and
  `api_key_id`, daily usage aggregates sum calls, tokens and priced amount per
  entry, principal, key, provider and model, and the run list and every cost
  breakdown filter by both.
- Alerts that reach people where they are: budget, credit and failed-run
  alerts go to members' own endpoints as their preferences allow, and to
  workspace team channels subscribed to them.
- Console: key limits and service principals under Settings › API, team
  channels under Settings › Notifications, run content under Settings ›
  Security, Govern › Budgets, virtual models under Build › Models, and entry
  and key filters under Observe › Runs.
- Ollama as a first-class provider: catalog sync with context length and
  capabilities, a version healthcheck, and the native backend through the
  server's OpenAI-compatible `/v1`.
- Anthropic models call tools natively, messages can carry images across
  adapters, and the OpenAI adapter passes `response_format`, `stop` and
  `seed`.
- Client examples in `examples/gateway/` and an OpenAI Python SDK
  compatibility suite in CI.

## Database Compatibility

- Fresh installations migrate from `base` to `20260927160000`.
- The supported N-1 upgrade range is `20260926110000..20260927160000`.
- Older or unknown development snapshots require a new database or an
  operator-managed export/import path.

This release adds seven migrations, all additive:

| Revision | Adds |
| -------- | ---- |
| `20260927100000` | API key limit columns (rate, daily requests and tokens, address and model allowlists) |
| `20260927110000` | `virtual_models` |
| `20260927120000` | `content_capture` on workspaces and API keys |
| `20260927130000` | `service_principals` and `api_keys.principal_id` |
| `20260927140000` | `runs.source`, `runs.api_key_id` and `usage_daily_aggregates` |
| `20260927150000` | `budgets` |
| `20260927160000` | scope and categories on notification endpoints |

Existing keys keep working unchanged, existing workspaces keep recording
content, existing runs read as `source = platform`, and existing notification
endpoints become members' own endpoints (`scope = user`).

## Upgrading

1. Run `alembic upgrade head` (the `migrate` service does this before the API
   starts).
2. If a proxy sits in front of the API, route `/v1/*` to the API as well as
   `/api/*`, without buffering; the production reference's Caddyfile does.
3. If any key will use an address allowlist, set `TRUSTED_PROXIES` to the
   proxies in front of the API; without it, the allowlist sees the proxy.
4. The outbox dispatcher now also runs the usage reconciler, which rebuilds
   each finished UTC day from the cost ledger
   (`USAGE_RECONCILE_INTERVAL_SECONDS`, hourly by default). No new service is
   needed.
5. Behaviour changes to review:
   - Tool calls now pass the same credit and budget checks as model calls, so
     exhausted credit with enforcement on refuses tool calls too.
   - Budget and credit alerts respect each member's `alert` category and go
     to their own endpoints as their delivery mode allows, not only to the
     inbox.
   - Run responses carry `source` and `api_key_id`, and the runs CSV export
     has two more columns at the end.

## Known Limitations

- A stream the client abandons ends its run as `CLIENT_DISCONNECTED`, but
  the model step stays `running` and its cost is not recorded.
- Budget reservations expire after about a minute instead of being released,
  and without Redis they are skipped, so concurrent calls can overshoot a
  budget by more than one call.
- Budget spend reads the daily aggregates for finished days and the cost
  ledger for today; a day's aggregate is complete once the reconciler has
  rebuilt it. Aggregates carry no error counts.
- Rehearsal runs are counted under `source = rehearsal`, apart from real
  traffic.
- On the OpenAI Responses API path, `stop` is refused and `seed` is not sent.
- Content capture is decided when a run starts; if the workspace setting
  cannot be read, content is withheld.
- The compatibility suite runs the OpenAI Python SDK in CI. The Node,
  LangChain and Agents SDK examples are provided for reference; LangChain and
  the Agents SDK call through the same Python client the suite drives.
