# SOIT v1.1.0 Governance Release Notes

Status: release evidence template. Publish only after the release commit is tagged as `v1.1.0` and the governance release evidence verifier passes against real command output.

## Highlights

- Plugin-first governance: MCP server and Skill artifacts are installed and governed through the Plugin module.
- Governed runtime calls: plugin-owned tools use policy gateways for workspace access, egress checks, controlled secret injection, audit evidence, and cost attribution.
- Observe governance surfaces: run replay, Audit Explorer, cost attribution, tool call evidence, citations, child runs, and response events are available from Observe.
- Regression as release gate: historical runs can become regression cases, and Agent publish can replay active cases before writing a release.
- Governance demo: the 20-minute demo covers permissions, secrets, call audit, cost attribution, replay, and regression evidence.

## Required Release Evidence

Before publishing:

```bash
cd server
uv run python scripts/verify_governance_demo.py --json-output ../docs/deployment/governance-demo-report.example.json
uv run python scripts/verify_governance_release.py ../docs/deployment/governance-release-v1.1.0-evidence.json
```

The final evidence file must be copied from `docs/deployment/governance-release-v1.1.0-evidence.example.json` and updated with real command output, a non-zero 40-character lowercase release commit SHA, a named `git_tag` record whose tag and commit match the release, and a named `release_notes_publication` record with the published HTTPS release URL.
