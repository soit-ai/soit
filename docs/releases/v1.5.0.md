# SOIT v1.5.0 Evaluation and Knowledge Sync Release Notes

Status: released on 2026-10-01 as tag `v1.5.0` (commit `d960d30`).

## Highlights

- The gateway serves the Anthropic Messages API: `POST /v1/messages`, whole
  or streamed in Anthropic's named events, and `POST /v1/messages/count_tokens`,
  so Claude Code and the Anthropic SDKs can be pointed at SOIT with
  `x-api-key` or a Bearer key. A call is an ordinary governed gateway run
  through the same policy chain as `/v1/chat/completions`, on whichever
  provider the model ref names. The official Anthropic Python SDK runs
  against the route in CI.
- Evaluation datasets are objects of their own: create, edit, import and
  export cases as JSONL, keep a revision history with content hashes, and run
  a dataset on demand on the published version, a draft or another model.
  Observe › Evaluations in the console shows datasets, cases, reports and
  versions; `soit dataset` and `soit eval run --fail-on-regression` bring the
  same checks to CI.
- Knowledge bases stay in step with an S3-compatible bucket or a website:
  sources sync on demand or on a cron schedule in the ingest worker, ingest
  new items, version changed ones, skip unchanged ones and optionally delete
  documents whose items disappeared. A failed sync shows in Observe dead
  letters as `knowledge_sync`.
- An agent moves in and out as a YAML or JSON file (`soit agent export` and
  `soit agent import`), and a trace exports as OTLP/JSON for an OpenTelemetry
  collector, Jaeger or Tempo, with no run content.
- The release workflow publishes the `soit` command line to PyPI from the
  release tag. The upload did not run for v1.5.0, and the distribution was
  renamed to `soit-cli` in v1.5.1, so install v1.5.1 or later with
  `uv tool install soit-cli`; the command stays `soit`.
- Runs carry their priced cost (`cost_amount`, `cost_currency`), the
  Workflows list shows node counts and recent outcomes, and a DeepSeek
  provider lists its models.
- Dependencies: LiteLLM 1.103.0, the OpenAI SDK 2.54.0, SQLModel 0.0.47,
  bcrypt 5 without passlib, pymilvus 2.5.18 and assistant-ui 0.15 in the
  console.

## Database Compatibility

- Fresh installations migrate from `base` to `20261001110000`.
- Two migrations are added:
  - `20261001100000` adds `regression_datasets` and
    `regression_dataset_versions`, creates one dataset (with one version
    holding its active cases) for every agent and dataset name that already
    has cases, and makes `regression_cases.source_run_id` nullable.
  - `20261001110000` adds `knowledge_sources`, `knowledge_source_items` and
    `knowledge_sync_runs`.
- The supported N-1 upgrade range is `20260927160000..20261001110000`: a
  v1.4.0 database (`20260927190000`) upgrades in place.
- Both migrations have a downgrade. Downgrading to `20260927190000` drops the
  datasets, their versions, and every knowledge source with its items and
  sync runs; documents already ingested stay. A case written without a source
  run gets an empty `source_run_id`. Restoring the backup taken before the
  upgrade is the preferred way back.

## Upgrading

1. Back up the database and object storage
   ([backup and restore runbook](../operations/backup-restore.md)).
2. Run `alembic upgrade head` (the compose `migrate` service does this), then
   restart the API, the workers and the web console on the new images.
3. Knowledge connector syncs run in the knowledge ingest worker and are on by
   default (`KNOWLEDGE_SYNC_WORKER_ENABLED=true`). The new
   `KNOWLEDGE_SYNC_*` settings in `server/.env.example` hold the poll
   interval, concurrency, schedule spacing and per-run size caps; their
   defaults need no change. A source on a private network needs that network
   in `EGRESS_PRIVATE_NETWORKS`.
4. Behaviour changes to review:
   - Retrying a task of a type nothing can re-execute is refused with
     `TASK_NOT_RERUNNABLE` (the `task_type` in the details) instead of a
     generic `409 CONFLICT`, and the task keeps its terminal status.
   - `/api/v1/images/*` results name the run artifact as `artifact_id`;
     `attachment_id` still carries the same id.
   - A virtual model's image call moves on to its next target when a target
     cannot carry an option the call asks for, instead of being refused by
     the first available target.
   - Azure AI MAI image edits refuse `n` and `size` before the call.
   - Passwords are checked with bcrypt 5 directly. Stored hashes verify
     unchanged, and a password past 72 bytes is cut there as before.
   - Every timestamp a model reads is an aware UTC datetime, and a model
     refuses a naive datetime. Extension packages that write naive
     datetimes through SOIT's models must pass aware ones.
   - The agent detail page no longer shows inputs that saved nothing
     (trigger, output schema, governance preview, alert threshold, rate
     limit, retry and on-failure settings).
   - The pre-rebuild console routes (`web/app/routes_old/`) are removed.

## Known Limitations

- `/v1/messages` accepts `thinking`, `cache_control`, `top_k`, `metadata`
  and `service_tier` and does not send them: prompt caching discounts and
  extended thinking are not available through the route, and responses carry
  no thinking blocks. `count_tokens` is SOIT's estimate, not the provider's
  tokenizer. The Message Batches and Files APIs are not served.
- The gateway does not serve OpenAI's `/v1/responses`.
- Knowledge connectors do not map the source system's access rights onto
  documents: everyone who can retrieve from the knowledge base can retrieve
  synced documents. OAuth and SaaS sources and authenticated or
  JavaScript-rendered websites are not included.
- `soit eval run` runs an agent's dataset synchronously; scheduled
  evaluation and evaluating subjects other than agents are not included.
- DeepSeek's model listing carries ids only, so context and output limits
  stay unset; DeepSeek has no embeddings endpoint.
- The v1.5.0 command line is not on PyPI: install `soit-cli` 1.5.1 or later,
  or install the v1.5.0 checkout from the repository (`uv tool install ./cli`).
- The known limitations of v1.4.0 still apply, except where the changelog
  lists them as fixed.
