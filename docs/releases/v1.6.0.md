# SOIT v1.6.0 Cost Reconciliation and Document Access Release Notes

Status: released on 2026-10-02 as tag `v1.6.0` (commit `05ed359`); `soit-cli` 1.6.0 is on PyPI.

## Highlights

- Costs can be checked against a provider's bill.
  `GET /api/v1/runs/costs/entries` filters by API key, principal, run
  source, model, provider, tool, port, operation, currency and pricing
  status, and each row says whether it is `priced`, `estimated`, `free` or
  `unpriced` (with the reason). `GET /api/v1/runs/costs/reconciliation`
  totals a half-open window per currency, apart from its estimated part,
  counts unpriced rows by reason and groups by model, provider, tool, key,
  principal, source, operation or day. Unpriced rows are never counted as
  zero, and currencies are never added together. Observe › Costs in the
  console shows the same and exports CSV to set beside a bill. See
  [Checking costs against a bill](../ledger.md#checking-costs-against-a-bill).
- Cost rows of model calls keep the provider's own ids (`upstream_id`, the
  response id, and `upstream_request_id`, from the response headers) for
  OpenAI, Anthropic, Gemini and LiteLLM, so a row can be found on the
  provider's side. The ledger contract moves to 1.1 with these two optional
  fields.
- A workspace decides what calls with no price do: **Calls with no price**
  in Settings › Security is `allow` (as before), `refuse_when_budgeted` or
  `refuse`. A refused call is answered `403` `PRICING_NOT_CONFIGURED` before
  the provider or tool is called, and is audited; a virtual model moves on
  to a priced target.
- Knowledge documents can be restricted. A restricted document is readable
  only by the workspace's Owners and Admins, the knowledge base's creator
  and holders of a `knowledge_document` read grant. Everyone else meets it
  nowhere: not in listings, not by id (`404`), and not in retrieval by any
  strategy, so not in agent RAG, workflow retrieve nodes, the
  `knowledge_query` tool or MCP. Restrictions are kept per document key, so
  new versions and connector syncs stay restricted, and take effect at once.
  **Access** on each document in the console restricts it and grants read
  to members. See [Knowledge access](../knowledge-access.md).
- What runs kept from earlier retrievals is read back by the reader's access
  now. Citations, `knowledge_query` results, source events, thread messages,
  tool results and replays leave out documents the reader may not read;
  step output summaries and an agent's retrieved context in an approval
  checkpoint are withheld whole when they came from such a document. Stored
  records are not changed, so lifting a restriction shows them again.
- A gateway pilot kit in `examples/pilot`: set up a provider, models, a
  failover virtual model, a limited key and a budget over the HTTP API,
  check allowed and refused calls, failover, idempotency, cost
  reconciliation and an evidence bundle, and tear it all down. A
  standard-library mock provider rehearses it without credentials.
- Includes the security fixes of v1.5.2: granting resource access takes a
  workspace Owner or Admin, and a document's `file_id` must name a file of
  the same knowledge base.

## Database Compatibility

- Fresh installations migrate from `base` to `20261002120000`.
- Three migrations are added:
  - `20261002100000` adds `upstream_id` and `upstream_request_id` to
    `run_cost_entries`, nullable and not unique.
  - `20261002110000` adds `unpriced_call_policy` to `workspaces`; existing
    workspaces get `allow`.
  - `20261002120000` adds `knowledge_document_restrictions`; nothing is
    restricted until someone restricts it.
- The supported N-1 upgrade range is `20260927160000..20261002120000`: a
  v1.5.x database (`20261001110000`) upgrades in place.
- All three migrations have a downgrade. Downgrading to `20261001110000`
  drops the provider ids, every workspace's unpriced call policy and every
  document restriction, so restricted documents become readable to everyone
  their knowledge base admits. Restoring the backup taken before the
  upgrade is the preferred way back.

## Upgrading

1. Back up the database and object storage
   ([backup and restore runbook](../operations/backup-restore.md)).
2. Run `alembic upgrade head` (the compose `migrate` service does this), then
   restart the API, the workers and the web console on the new images. No
   setting is added.
3. Behaviour changes to review:
   - Evidence bundles and ledger exports declare ledger contract `1.1`.
     Cost records may carry `upstream_id` and `upstream_request_id`; a
     consumer that rejects unknown fields must accept them.
   - Copies kept in runs, responses, threads and tasks now follow the
     reader's current access to knowledge, including the visibility rules
     that existed before: a member who cannot read someone else's private
     knowledge base, or a base not shared with their workspace, no longer
     sees its documents in the runs of those who could. Items are dropped
     from lists, totals recounted, and other copies replaced by a withheld
     marker.
   - The keyword fallback of retrieval answers from the latest version of
     each document only, as the vector index does.
   - Workflow steps record the documents their output named in a
     `knowledge_documents` metric.
   - The Overview spend tile and the dashboard's run costs no longer add
     currencies together: a run priced in more than one currency has no
     single dashboard cost, and run detail totals each currency apart.
     Unpriced entries add nothing, so a run with only those shows a dash,
     not zero.

## Known Limitations

- Cost reconciliation lines the ledger up beside a bill; SOIT does not
  import or read provider bills, and the console says the bill itself has
  not been checked.
- Text a model wrote from retrieved documents (a response's answer,
  assistant messages, later workflow nodes that used it) is shown as
  written to every reader; only its citations are filtered.
- A run records how many documents retrieval left out, not which grant or
  role let it read each one.
- A document read grant names one member or service principal; there are
  no groups. Connector-synced documents do not inherit the source system's
  permissions.
- Steps recorded before v1.6.0 do not know which documents they came from:
  a `knowledge_query` step's summary is withheld when the reader may not
  read some document of the knowledge base it queried, and a workflow
  retrieve step's when the reader may not read some document anywhere in
  the workspace.
- The known limitations of v1.5.0 still apply, except where the changelog
  lists them as fixed.
