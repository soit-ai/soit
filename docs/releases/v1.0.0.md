# SOIT v1.0.0 Release Notes

Status: release evidence template. Publish only after the release commit is tagged as `v1.0.0` and `verify_phase1_release.py` passes against real command output with a non-zero 40-character release commit SHA.

## Scope

- ModelHub 1.0 provider setup, diagnostics, and runtime integration.
- Knowledge 1.0 upload, indexing, query, and citation path.
- Agent 1.0 publish and execute path with bindings.
- Chat 1.0 response execution and thread evidence.
- Runs and Observe 1.0 run detail, steps, tool calls, costs, citations, and audit evidence.
- Workflow 1.0 builder, publish, execute, monitor, retry, replay, and run linkage.
- Workspace/settings stabilization for the 1.0 self-hosted path.
- Quickstart documentation and release acceptance evidence gates.

## Database Compatibility

- Fresh installations upgrade from `base` to `20260803090000`.
- The supported N-1 upgrade is `20260718140000..20260803090000`.
- Older or unknown development snapshots require a new database or an operator-managed export/import path.

## Required Release Evidence

Before publishing this release, copy `docs/deployment/phase1-release-v1.0.0-evidence.example.json` to `docs/deployment/phase1-release-v1.0.0-evidence.json`, replace all example references with real release evidence, and validate it from `server/` with repository-root checks enabled:

```bash
uv run python scripts/verify_phase1_release.py ../docs/deployment/phase1-release-v1.0.0-evidence.json --repo-root ..
```

The final evidence must include Quickstart deployment, manual Owner UI and Chain A/B acceptance, at least two live model-provider spot-checks, Alembic migration evidence, 1 to 3 non-developer Chain A feedback records, quality-gate output, unique aggregate evidence refs, a non-zero 40-character release commit SHA, a clean worktree at tag creation, release-notes publication evidence, local evidence files that exist under the repository root, and a `v1.0.0` tag that points to the recorded commit.
