# SOIT v1.8.0 Approval Safeguards Release Notes

Status: prepared on 2026-10-03; not yet tagged.

## Highlights

- **No self-approval, per workspace.** A workspace Owner or Admin can require
  another approver for every request: **Settings › Security › Self-approval**,
  or `forbid_self_approval` on `PATCH /api/v1/workspaces/{id}`. Whoever
  opened a request is then answered `403` when approving it, on every path
  including the chat client's resume; they may still reject or cancel it, and
  any other approver still approves. An agent run's requester is the member
  who ran it, so their own chat cannot approve its tool calls either. Off by
  default.
- **Reminders before a deadline.** An undecided request reminds its approvers
  once: `APPROVAL_REMINDER_LEAD_SECONDS` (an hour by default) before its
  deadline, or half-way through a request open for less than twice that. The
  reminder is a new `approval.due_soon` event and a `task` notification,
  through the same preferences and channels as the other approval
  notifications. `0` sends no reminders.
- Approval responses carry `can_approve` for the caller, beside `can_decide`,
  and the console offers Approve only where it is allowed.
- See [Approvals](../approvals.md).

## Database Compatibility

- Fresh installations migrate from `base` to `20261003110000`.
- One migration is added: `20261003110000` adds
  `workspaces.forbid_self_approval` (null, so every workspace keeps allowing
  self-approval) and `approval_requests.remind_at` (null for existing
  requests, which are therefore not reminded).
- The supported N-1 upgrade range is `20260927160000..20261003110000`: a
  v1.7.0 database (`20261003100000`) upgrades in place.
- The migration has a downgrade that drops both columns.

## Upgrading

1. Back up the database and object storage
   ([backup and restore runbook](../operations/backup-restore.md)).
2. Run `alembic upgrade head` (the compose `migrate` service does this), then
   restart the API, the workers and the web console on the new images.
3. `APPROVAL_REMINDER_LEAD_SECONDS` is new and optional (an hour by default);
   set it on the API service, where the approval sweeper runs, to change or
   switch off reminders.
4. Behaviour changes to review:
   - Approvers of requests with a deadline receive one more notification per
     request, the reminder, in the `task` category.
   - A client that reads approval responses sees the new `can_approve`
     field; nothing it relied on changed.

## Known Limitations

- The self-approval setting applies to approving only; a requester can still
  reject or cancel their own request, by design.
- A request is reminded once, at a time fixed when it was opened; changing
  `APPROVAL_REMINDER_LEAD_SECONDS` does not move reminders already scheduled.
- Escalation to other approvers when a deadline passes, assigning requests by
  policy rule, and multi-step or quorum approvals remain outside Community.
- The known limitations of v1.7.0 still apply.
