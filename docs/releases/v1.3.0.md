# SOIT v1.3.0 Tools, MCP and Evidence Release Notes

Status: release candidate notes. Publish only after the release commit is
tagged as `v1.3.0` and `quality.yml` and `security.yml` pass on that commit.

## Highlights

- SOIT as an MCP server: `POST /mcp` serves a workspace's governed tools to
  Claude Code, Cursor and any other MCP client, statelessly, in the
  `2026-07-28` revision (no handshake, `server/discover`, per-request
  version and capabilities, checked `Mcp-Method` and `Mcp-Name` headers) and
  in the earlier revisions that open with `initialize`. Clients connect with
  a SOIT API key; the endpoint publishes OAuth 2.1 protected resource
  metadata (RFC 9728) and challenges requests without a credential. See
  [docs/mcp.md](../mcp.md) and [examples/mcp/](../../examples/mcp/).
- Direct tool calls: `POST /api/v1/tools/{ref}/invoke` calls one tool by
  reference through the same governed gateway as agents (secrets, egress,
  rate limits, budgets, audit, cost), as a run with `mode=tool`.
  `Idempotency-Key` makes a call safe to retry, and a tool that needs
  approval answers `202` until a reviewer decides. `GET /api/v1/tools` lists
  what a caller may invoke. See [docs/gateway.md](../gateway.md#calling-tools).
- Keys limited to some tools: `allowed_tools` on API keys narrows the tools a
  key sees and invokes, from the tools API, MCP and runs it starts.
- Run evidence bundles: `GET /api/v1/runs/{run_id}/evidence` returns a
  deterministic zip of a run's ledger records, tool calls, approvals,
  citations, content safety findings, policy bundle ids and governance
  matrix, with a manifest and `SHA256SUMS`, respecting content-free
  workspaces. See [docs/ledger.md](../ledger.md).
- A versioned ledger contract (`ledger_spec.schema.json`, version 1.0) and
  ledger exports of runs, steps, costs, audit and outbox events by window,
  as JSON Lines or CSV, audited as they are taken.
- Model replays: every agent's regression set replayed on a candidate model
  next to the one it uses, comparing pass rate, latency and cost with the
  cases that regressed or were fixed, from Build › Models or
  `POST /api/v1/evaluations/model-replays`. See
  [docs/model-replays.md](../model-replays.md).
- The `soit` command line: `login`, `run`, `eval` (a model replay that can
  fail a CI step on regressions) and `export` (evidence bundles with their
  digest checked, and ledger records). See [cli/README.md](../../cli/README.md).
- Tenant-wide knowledge sharing: knowledge bases with `tenant` visibility are
  readable and queryable, never changed, from every workspace of the tenant.
- Workspace personal data handling: what the built-in content safety rules do
  with personal data entering and leaving the runtime can be set per
  workspace and direction.
- Console: Allowed tools on keys and a Connect a client panel under Settings
  › API, Regression replays under Build › Models, Shared with us under Build
  › Knowledge, personal data handling under Settings › Security, and server
  evidence bundles and CSV exports under Observe and Govern.

## Database Compatibility

- Fresh installations migrate from `base` to `20260927190000`.
- The supported N-1 upgrade range is `20260927160000..20260927190000`.
- Older or unknown development snapshots require a new database or an
  operator-managed export/import path.

This release adds three migrations, all additive:

| Revision | Adds |
| -------- | ---- |
| `20260927170000` | `pii_action_inbound` and `pii_action_outbound` on workspaces |
| `20260927180000` | `allowed_tools_json` on API keys |
| `20260927190000` | `regression_model_replays` |

Existing workspaces follow the deployment's personal data action, and
existing keys may invoke every tool of their workspace.

## Upgrading

1. Run `alembic upgrade head` (the `migrate` service does this before the API
   starts).
2. If a proxy sits in front of the API, route `/mcp` and
   `/.well-known/oauth-protected-resource*` to the API as well as `/api/*`
   and `/v1/*`; the production reference's Caddyfile does.
3. Set `MCP_RESOURCE_URL` to the public URL of `/mcp` when a proxy rewrites
   the host (the production compose file derives it from
   `SOIT_PUBLIC_HOSTNAME`). `MCP_ALLOWED_ORIGINS` admits browser origins other
   than the endpoint's own, and `MCP_AUTHORIZATION_SERVERS` publishes
   authorization servers in the metadata; both default to none.
4. Behaviour changes to review:
   - Knowledge bases with `tenant` visibility, which until now behaved as
     `workspace`, become readable from the tenant's other workspaces.
     Review which knowledge bases carry it before upgrading.
   - A key's `allowed_tools` also bounds runs the key starts: an agent run
     through a limited key cannot call a tool outside the list.
   - Agents and workflows can call the tools of MCP servers again; they
     failed with "MCP tool invocation requires db and ctx".
   - The API builds its service container at startup, so a wiring failure
     stops the API from starting instead of surfacing on a later request.
   - The run detail's Evidence bundle button downloads the server's zip
     instead of saving the page's JSON.
   - `/mcp` and `/.well-known/*` answer their protocols' bare shapes, not
     SOIT's response envelope.

## Known Limitations

- A direct tool call that waits for approval runs only when the caller sends
  it again, with the same key (or, over MCP, the same arguments); nothing
  runs it on the caller's behalf.
- The MCP endpoint serves tools only: no resources, prompts, sampling,
  elicitation, subscriptions or progress notifications. SOIT authenticates
  MCP clients with its API keys and does not issue OAuth tokens itself.
- SOIT's adapter that calls external MCP servers still targets the MCP SDK v1
  line and does not speak the `2026-07-28` revision to them.
- A key's calls-per-minute and daily limits count model calls; tool calls are
  held by the member's tool limits, the key's allowed tools and budgets.
- A model replay runs every case before its request answers, at most 200
  cases, and covers agents' regression sets only.
- Ledger exports cover at most 92 days per request.
- Shared knowledge is read in its home workspace and cannot yet be bound to
  another workspace's agents; members who are Viewers in their own workspace
  can open it but not query it.
- The workspace personal data action applies to the built-in content safety
  provider, not to an external classifier.
- The CLI is installed from the repository (`uv tool install ./cli`); it is
  not published to a package index yet.
- The compatibility suite drives the OpenAI Python SDK, the MCP Python SDK
  (against the `initialize` revisions it implements) and the `soit` CLI; the
  `2026-07-28` MCP revision is covered by protocol tests, as no SDK in CI
  implements it yet.
